# Как поднять ufo.gram из пепла

Короткий ответ: **отдай Клоду папку `C:\ufogram-backup\<дата>` и скажи
«восстанавливай».** Дальше можно не читать — остальное тут для случая,
когда Клода рядом нет.

---

## Что нужно сохранить

Система состоит из четырёх частей, и потеря любой означает разное.

**Код** — лежит в git, ветка `feat/ufogram-reactions-parsing`.
Восстанавливается клонированием, ничего делать не надо.

**База данных** — аккаунты, каналы, назначения, очередь комментариев,
история. Без неё система не знает, кто на что подписан и что уже сделано.
Восстанавливается из `gramgpt.dump`.

**Файлы сессий Telegram** — самое незаменимое. Файл сессии это и есть
вход в аккаунт. Потеряв его, войти можно только заново, по SMS, на каждый
из полутора сотен номеров. **В git их нет и быть не должно.**

**Настройки `.env`** — ключи LLM, доступы к базе и прокси. Тоже не в git.

**Память Redis** — реестр ограниченных аккаунтов со сроками, суточные
нормы, счётчики. Без неё система заработает, но забудет, кто ограничен, и
отправит забаненный аккаунт писать — он получит ограничение повторно и
уже дольше.

---

## Резервная копия

```
.\backup.ps1
```

Кладёт всё перечисленное в `C:\ufogram-backup\<дата_время>`. Копии старше
двух недель удаляются сами.

Делать хотя бы раз в сутки. Лучше — держать папку ещё и вне этого
компьютера: диск умирает вместе со всем сразу.

---

## Восстановление с нуля

### 1. Код

Если в комплекте есть `ufogram-code.bundle` — берём его. Это весь
репозиторий одним файлом: ветки, коммиты, история. Так надёжнее, чем
тянуть с GitHub: там может не оказаться последних правок, если их не
успели отправить.

```
git clone ufogram-code.bundle tg_manager1
cd tg_manager1
git checkout feat/ufogram-reactions-parsing
```

Если файла нет — с GitHub:

```
git clone https://github.com/xdsnich/tgmanage.git tg_manager1
cd tg_manager1
git checkout feat/ufogram-reactions-parsing
```

Дальше в обоих случаях:

```
python -m venv .venv
.\.venv\Scripts\pip install -r requirements.txt
```

### 2. База

Нужны установленные PostgreSQL и Redis.

```
createdb -U postgres gramgpt
psql -U postgres -c "CREATE USER gramgpt WITH PASSWORD 'gramgpt'; GRANT ALL ON DATABASE gramgpt TO gramgpt;"
pg_restore -h localhost -U gramgpt -d gramgpt --clean --if-exists gramgpt.dump
```

Если `pg_restore` ругается на владельцев объектов — добавь `--no-owner`.

### 3. Сессии и настройки

```
папка sessions  →  tg_manager1\api\sessions\
api_.env        →  tg_manager1\api\.env
.env            →  tg_manager1\.env
```

Имена файлов сессий менять нельзя: система ищет их по номеру телефона.

### 4. Память

```
python restore_redis.py C:\ufogram-backup\<дата>\redis-keys.json
```

### 5. Запуск

```
.\start_all.ps1
```

Проверить, что поднялось:

```
Get-Content logs\celery_worker.console.log -Tail 20
```

Должна быть строка «Движок прогрет» и ни одного `Traceback`.

## Что проверить после восстановления

**Кампания включена?** В базе `campaigns` строка 143 должна быть
`status = 'active'`.

**Есть ли рабочие пары?** Если `campaign_channel_assignments` пуста, писать
будет некуда — все посты уйдут с отказом «никто не вступил в обсуждение».
Такое уже случалось: перестройка плана кампании стирает эту таблицу
целиком. Восстановить можно из `account_subscriptions` и истории
комментариев — Клод знает как.

**Идут ли комментарии?** В журнале должны появляться строки
`[realtime] отправлено N`.

---

## Чего резервная копия не спасёт

**Ограничения Telegram.** Если аккаунт забанен — он забанен, файл сессии
этого не меняет.

**Прокси.** Они снаружи, у поставщика. Умрут — менять придётся вручную.

**Профили антидетекта.** Они живут в своей программе, отдельно.
